Nivel 01 Prompt Una instrucción de texto. Sin herramientas, sin memoria, sin persistencia.

Llevas meses hablando con la IA. Pero cada conversación empieza de cero. Explicas el contexto, el tono, el objetivo cada vez. La IA responde bien, pero tú eres quien lleva el peso mental de la tarea.

Un prompt bien escrito, con contexto, objetivo y restricciones claras, es la diferencia entre una respuesta genérica y una que sirve de verdad. El punto de partida de todo.

El límite Funciona perfectamente para tareas únicas. El problema llega cuando esa misma tarea se repite cuarenta veces al mes. Y cada vez hay que escribir el prompt desde cero.

Nivel 02 Skill Un prompt especializado con un nombre y un disparador. Reutilizable, invocable, transferible.

Identificas tres tareas que el equipo repite cada semana: el brief de un prospecto antes de una llamada, el recap de una reunión, el email de seguimiento. En lugar de re-escribir el prompt, lo encapsulas.

Le das un nombre, un disparador. Ahora existe como capacidad: cualquiera del equipo puede invocarla con un comando. La consistencia dejó de depender de quién tenga el prompt guardado en sus notas.

El límite La Skill sabe hacer su tarea. No sabe quién eres, dónde trabajas, ni qué contexto tiene tu empresa. Cada ejecución sigue siendo una conversación nueva para la IA.

Nivel 03 Semiagente Una Skill conectada al mundo real. El humano supervisa cada paso: la IA ejecuta con herramientas.

La Skill de brief de prospecto sería mucho más poderosa si pudiera leer el CRM directamente. La de recap de reunión debería crear la tarea en ClickUp automáticamente. Para eso, la IA necesita herramientas reales.

El humano sigue en el loop y valida cada paso antes de continuar. Pero ya no copia y pega datos entre sistemas. La productividad salta de inmediato.

MCP · Model Context Protocol

El puente entre la IA y un sistema externo. HubSpot MCP, ClickUp MCP, GitHub MCP: cada uno le da a la IA acceso directo para leer y actuar sobre datos reales. Sin MCP, la IA solo ve texto.

El límite Poderoso. Pero depende de que alguien esté mirando. Si el humano no está presente para aprobar cada paso, el semiagente se detiene.

Nivel 04 Agente Razona, actúa, observa, vuelve a razonar. Loop autónomo con herramientas reales.

Le das el objetivo, no los pasos. "Genera el reporte del sprint activo para los 5 equipos." La IA decide qué herramientas usar, en qué orden, cómo manejar los errores. Tú recibes el resultado: el proceso, invisible.

La diferencia con el semiagente no es técnica: es la pregunta que hace el humano. En el semiagente, "¿apruebo este paso?". En el agente, "¿el resultado cumplió el objetivo?"

El límite Un agente hace una cosa bien. Cuando el problema tiene muchas partes independientes que pueden ejecutarse en paralelo, la solución es coordinar varios agentes.

Nivel 05 Workflow Múltiples agentes coordinados por un orquestador. Cada parte opera de forma independiente.

The Sprint Intelligence system queries 5 teams, normalizes data, calculates KPIs y genera un dashboard. Ningún agente solo puede hacer todo eso de forma eficiente. Cinco agentes coordinados, sí.

Un orquestador distribuye el trabajo, gestiona dependencias, consolida resultados. El humano da el objetivo final y recibe el entregable. Lo que ocurre en medio es invisible. Eso es exactamente el punto.

El techo del espectro No hay un nivel por encima del workflow. La escala se resuelve aquí: más agentes, mejores MCPs, objetivos más grandes. La arquitectura escala sin que la supervisión tenga que escalar con ella.

Una nota sobre el entorno

El Project no es un nivel.

Un Project es el entorno donde viven los niveles: instrucciones permanentes para la IA, archivos de contexto de tu empresa, MCPs conectados, Skills organizadas. No es una forma de automatización: es el lugar desde donde opera todo lo demás.

Los niveles son los actores. El Project es el escenario.

Prompt

La tarea es única. Un prompt bien escrito es la herramienta correcta. No sobre-ingenieres.

Skill

Se repite y es genérica. Encapsula el prompt en una Skill invocable. Sin contexto, sin MCPs.

Skill en Project

Se repite y necesita contexto. La Skill vive dentro de un Project que le da ese mundo de forma persistente.

Semiagente

Herramientas reales con supervisión humana por paso. La validación es parte del diseño, no un defecto.

Agente

Herramientas reales, objetivo único, sin supervisión de proceso. El humano evalúa el resultado final.

Workflow

Problema multi-parte. Diseña un orquestador que coordine agentes especializados en paralelo.
